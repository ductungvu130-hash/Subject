2 Kiến thức cốt lõi (Từ Slide Bài Giảng)

1. Lập trình Bất đồng bộ (Async/Await)

Đề thi bắt buộc sử dụng async/await trong Repository và Controller để không block thread chính, cải thiện hiệu năng xử lý (I/O-bound operations).

  • Task / Task<T>: Đại diện cho một hành động bất đồng bộ. Thay vì trả về List<Book>, ta khai báo trả về Task<List<Book>>.
  • async: Từ khóa đặt trước tên hàm báo hiệu hàm này chứa xử lý bất đồng bộ. (VD: public async Task<IActionResult> GetAll())
  • await: Đợi một Task hoàn thành mà không block hệ thống. Chỉ được dùng bên trong một hàm async. (VD: await _context.SaveChangesAsync();)

2. Entity Framework Core & Migrations

EF Core là Object-Relational Mapper (ORM) giúp lập trình viên thao tác với DB bằng C# objects (Code-First Approach) thay vì viết SQL thuần.

Data Annotations (Bắt buộc nhớ)
  • [Key]: Đánh dấu Khóa chính (Primary Key). Mặc định Id đã là PK.
  • [Required]: Bắt buộc nhập (NOT NULL).
  • [MaxLength(100)] / [StringLength(100)]: Độ dài chuỗi tối đa.
  • [Range(0, 100)]: Giới hạn giá trị của số.
  • [EmailAddress]: Validate định dạng Email.
  • [Column("Name")]: Đổi tên cột mapping xuống DB.
Lệnh Migration

Giúp đồng bộ cấu trúc Model (C#) xuống Database (SQL Server).

  • dotnet ef migrations add <Name>
    Tạo bản snapshot cấu trúc DB.
  • dotnet ef database update
    Thực thi migration sinh ra các bảng trong DB.
  • dotnet ef migrations remove
    Xóa/rollback migration gần nhất chưa update.
Lưu ý Inheritance (TPH): Trong EF Core, pattern Table-per-Hierarchy (TPH) gom các class có quan hệ cha-con (VD: Book cha, EBook con) vào chung 1 bảng và phân biệt bằng cột Discriminator.

3. Dependency Injection (DI) & API Controllers

Cơ chế quản lý Dependency và thiết kế RESTful API.

  • Dependency Injection (DI): Pattern giúp giảm phụ thuộc cứng (loose coupling) giữa các class. Thay vì new Repository(), ta dùng Constructor Injection để tiêm các Service vào Controller. Cấu hình tại Program.cs:
    builder.Services.AddScoped<IRepository, Repository>();
  • Controller: Là class xử lý request từ Client, kế thừa ControllerBase, cần có Attribute [ApiController] và [Route("api/[controller]")].
  • HTTP Methods: [HttpGet] (Lấy dữ liệu), [HttpPost] (Tạo mới), [HttpPut] (Cập nhật), [HttpDelete] (Xóa).

4. Authentication & Authorization (Bảo mật)

Các khái niệm cốt lõi bảo vệ ứng dụng (Rất hay hỏi lý thuyết).

Khái niệm cốt lõi
  • Authentication (Xác thực): Xác định người dùng là ai (Bạn là ai?). Ví dụ đăng nhập bằng JWT hoặc Cookie. Lỗi nếu sai: 401 Unauthorized (tương ứng với lệnh Challenge).
  • Authorization (Phân quyền): Xác định người dùng được phép làm gì (Bạn được làm gì?). Lỗi nếu sai: 403 Forbidden (tương ứng với lệnh Forbid).
Cơ chế Authorization thường dùng
  • Role-based: Dựa trên vai trò. VD: [Authorize(Roles = "Admin")].
  • Claim-based / Policy-based: Phân quyền chi tiết hơn dựa trên thông tin cụ thể (vd: Tuổi > 18, Thuộc phòng ban IT).
  • Lưu ý thứ tự Middleware: UseAuthentication() phải luôn đặt trước UseAuthorization().

5. Kiểm thử phần mềm (Testing)

Unit Test (Kiểm thử đơn vị)
  • Chiếm khoảng 70% lượng test. Test một thành phần nhỏ nhất (Class/Method).
  • Chạy cực nhanh, KHÔNG gọi Database thật hay API bên ngoài.
  • Công cụ: xUnit (Framework test), Moq (Giả lập/Mock các lớp phụ thuộc như IRepository), FluentAssertions.
  • Mô hình AAA: Arrange (Chuẩn bị data/mock) -> Act (Gọi hàm cần test) -> Assert (Kiểm tra kết quả).
Integration Test (Kiểm thử tích hợp)
  • Chiếm khoảng 30%. Test sự phối hợp giữa các layer: Controller -> Service -> Database.
  • Chạy chậm hơn Unit Test. Thường dùng DB ảo (In-Memory / SQLite) để tránh ghi rác vào DB thật.
  • Công cụ: WebApplicationFactory để tạo một TestServer giả lập môi trường gọi API thực tế.

6. Kiến thức nâng cao (SignalR & Lỗ hổng bảo mật)

  • SignalR (Real-time): Thư viện hỗ trợ giao tiếp thời gian thực trên ASP.NET Core (Ứng dụng Live Chat, Live Dashboard). Trọng tâm sử dụng mô hình Hub-based. Tự động tìm cơ chế kết nối tốt nhất: WebSockets -> Server-Sent Events (SSE) -> Long Polling.
  • Các lỗ hổng bảo mật hay gặp:
    • SQL Injection: Chèn mã SQL độc hại. Cách phòng: Dùng ORM (như Entity Framework) hoặc Parameterized queries.
    • XSS (Cross-Site Scripting): Chèn script độc (JS) vào giao diện. Cách phòng: Escape output HTML, dùng thẻ bảo mật (CSP).
    • CSRF (Cross-Site Request Forgery): Giả mạo yêu cầu từ user đã login. Cách phòng: Dùng [ValidateAntiForgeryToken].
    • Broken Authentication: Lộ mật khẩu. Cách phòng: Băm mật khẩu (bcrypt, PBKDF2), giới hạn thời gian (Expiration) cho JWT Token.

7. C# OOP Cơ Bản (Nền tảng viết Model/Controller)

Model, Repository, Controller trong đề thi đều là class C# chuẩn OOP — nắm chắc phần này để không bị lúng túng khi code Property, Constructor hay kế thừa.

Class, Object & Access Modifier
  • Class là khuôn mẫu (template); Object là thể hiện (instance) được tạo từ class bằng new.
  • Field (biến trong class) và Method gọi chung là Class Members.
  • public: truy cập được từ mọi nơi. private: chỉ truy cập trong chính class đó — dùng để hiện thực Encapsulation (che giấu dữ liệu nhạy cảm).
Property (get/set) & Constructor
  • Property = kết hợp field + method, có get/set. Auto-property (public string Name { get; set; }) là cách viết tắt không cần khai báo field riêng — chính là cú pháp dùng trong toàn bộ Model của đề thi.
  • Constructor: method đặc biệt trùng tên class, chạy khi new object, dùng để gán giá trị khởi tạo (VD: constructor nhận AppDbContext qua Dependency Injection trong Repository/Controller).
Inheritance & Polymorphism
  • Inheritance: dùng dấu : để kế thừa. VD ControllerBase là base class, ItemsController : ControllerBase là derived class.
  • Polymorphism: override method của lớp cha bằng cặp từ khóa virtual (lớp cha) / override (lớp con).
Abstract Class vs Interface
  • Abstract class: không tạo object trực tiếp được, có thể chứa cả method có thân (body) lẫn method trừu tượng (không có thân, bắt buộc lớp con hiện thực).
  • Interface: chỉ chứa "chữ ký" method/property, không có thân — đúng bản chất của IItemRepository, IRepository<T> trong đề thi (định nghĩa hợp đồng, class thật implement).

8. Vòng đời Service trong Dependency Injection

Khi đăng ký DI trong Program.cs (builder.Services.Add...), phải chọn đúng vòng đời — chọn sai AppDbContext là Singleton sẽ gây lỗi nghiêm trọng khi nhiều request truy cập đồng thời.

  • AddTransient<T>: Tạo object mới mỗi lần được inject — dùng cho service nhẹ, không giữ state.
  • AddScoped<T>: Tạo 1 object dùng chung trong 1 HTTP request — đây là lifetime chuẩn cho AppDbContext và Repository trong đề thi.
  • AddSingleton<T>: Tạo 1 object duy nhất dùng chung cho toàn bộ ứng dụng — dùng cho service không đổi theo request (VD: cấu hình, cache tĩnh). Không dùng cho DbContext.

9. Client-Server & ASP.NET Core Platform

  • Client-Server: Client gửi Request → Server xử lý/truy vấn dữ liệu → Server trả về Response. Giao tiếp qua HTTP/HTTPS, thường dùng REST API + JSON — đúng mô hình đề thi yêu cầu xây dựng.
  • .NET Framework vs .NET Core: .NET Framework chỉ chạy Windows, đóng nguồn, DI phải dùng thư viện ngoài (Unity/Ninject). .NET Core đa nền tảng (Windows/macOS/Linux), mã nguồn mở, có DI tích hợp sẵn, middleware pipeline linh hoạt — đây là nền tảng ASP.NET Core Web API dùng trong toàn bộ đề thi.
  • Model trong EF Core gọi là POCO class (Plain Old CLR Object) — class thuần chỉ chứa property, không phụ thuộc trực tiếp vào EF Core.

    }

5 Repository Layer

Các method chuẩn bắt buộc dùng lập trình bất đồng bộ (async / await). Nhớ Include các Navigation Properties khi cần.

public interface IPetRepository // Kì 1: IFruitRepository
{
    Task<List<Pet>> GetAll();
    Task<Pet?> GetById(int id);
    Task Add(Pet pet);
    Task Update(Pet pet);
    Task Delete(int id);
    Task<List<Pet>> GetByCategoryId(int categoryId);
}

public class PetRepository : IPetRepository
{
    private readonly AppDbContext _context;
    public PetRepository(AppDbContext context) => _context = context;

    public async Task<List<Pet>> GetAll() =>
        await _context.Pets.Include(p => p.Category).ToListAsync();

    public async Task<Pet?> GetById(int id) =>
        await _context.Pets.Include(p => p.Category)
            .FirstOrDefaultAsync(p => p.Id == id);

    public async Task Add(Pet pet)
    {
        _context.Pets.Add(pet);
        await _context.SaveChangesAsync();
    }

    public async Task Update(Pet pet)
    {
        _context.Pets.Update(pet);
        await _context.SaveChangesAsync();
    }

    public async Task Delete(int id)
    {
        var pet = await _context.Pets.FindAsync(id);
        if (pet != null)
        {
            _context.Pets.Remove(pet);
            await _context.SaveChangesAsync();
        }
    }

    public async Task<List<Pet>> GetByCategoryId(int categoryId) =>
        await _context.Pets.Where(p => p.CategoryId == categoryId).ToListAsync();
}

6 API Controllers & Routing

Đề yêu cầu validate Foreign Key (CategoryId) khi Create/Update. Trả về 400 Bad Request nếu lỗi, 404 Not Found nếu không tìm thấy.

[ApiController]
[Route("api/[controller]")]
public class PetsController : ControllerBase // Kì 1: FruitsController
{
    private readonly IPetRepository _repo;
    private readonly AppDbContext _context; // Dùng để check FK tồn tại
    
    public PetsController(IPetRepository repo, AppDbContext context)
    {
        _repo = repo;
        _context = context;
    }

    [HttpGet]
    [AllowAnonymous] // Public access
    public async Task<IActionResult> GetAll()
    {
        var pets = await _repo.GetAll();
        
        // Đề Kì 1 yêu cầu trả về theo định dạng Nested hoặc Flat.
        // Format Flat dễ làm hơn:
        var result = pets.Select(p => new
        {
            id = p.Id,
            name = p.Name,
            breed = p.Breed,
            price = p.Price,
            categoryId = p.CategoryId,
            categoryName = p.Category?.Name
        });
        return Ok(result);
    }

    [HttpPost]
    [Authorize(Roles = "Admin")]
    public async Task<IActionResult> Create([FromBody] Pet pet)
    {
        if (!ModelState.IsValid) return BadRequest(ModelState);

        // Validate CategoryId exist
        if (!await _context.PetCategories.AnyAsync(c => c.Id == pet.CategoryId))
            return BadRequest("CategoryId does not exist.");

        await _repo.Add(pet);
        return CreatedAtAction(nameof(GetById), new { id = pet.Id }, pet);
    }

    [HttpGet("{id}")]
    [AllowAnonymous]
    public async Task<IActionResult> GetById(int id)
    {
        var pet = await _repo.GetById(id);
        if (pet == null) return NotFound();
        return Ok(pet);
    }

    [HttpPut("{id}")]
    [Authorize(Roles = "Admin")]
    public async Task<IActionResult> Update(int id, [FromBody] Pet pet)
    {
        if (id != pet.Id) return BadRequest("Id không khớp.");
        if (!ModelState.IsValid) return BadRequest(ModelState);

        var existing = await _repo.GetById(id);
        if (existing == null) return NotFound();

        if (!await _context.PetCategories.AnyAsync(c => c.Id == pet.CategoryId))
            return BadRequest("CategoryId does not exist.");

        await _repo.Update(pet);
        return NoContent();
    }

    [HttpDelete("{id}")]
    [Authorize(Roles = "Admin")]
    public async Task<IActionResult> Delete(int id)
    {
        var existing = await _repo.GetById(id);
        if (existing == null) return NotFound();

        await _repo.Delete(id);
        return NoContent();
    }
}

7 Logic tạo Order (Nơi dễ mất điểm nhất)

Các bước bắt buộc phải code (Create)

  • Extract UserId từ JWT Token (không lấy từ Body)
  • Gán OrderDate = thời gian server hiện tại
  • Gán Status = "Pending"
  • Lấy UnitPrice từ Product hiện tại
  • Tự động tính TotalAmount = sum(Qty * UnitPrice)

Các Validate bắt buộc (Create & Get)

  • Product/Pet/Fruit ID phải tồn tại trong DB
  • Quantity mua phải > 0
  • Số lượng hàng tồn (Stock/Quantity) phải đủ
  • Quan trọng (GET): User chỉ được xem order của chính mình (check role + userId)
[HttpPost]
[Authorize] // Yêu cầu đã đăng nhập (Admin hoặc Customer đều được)
public async Task<IActionResult> CreateOrder([FromBody] CreateOrderDto dto)
{
    // 1. Extract UserId từ JWT
    var userIdClaim = User.FindFirst(ClaimTypes.NameIdentifier)?.Value;
    if (string.IsNullOrEmpty(userIdClaim)) return Unauthorized();
    int userId = int.Parse(userIdClaim);

    // 2. Khởi tạo Order
    var order = new PurchaseOrder
    {
        UserId = userId,
        OrderDate = DateTime.Now,
        Status = "Pending"
    };

    decimal totalAmount = 0;

    // 3. Xử lý từng Item
    foreach (var itemDto in dto.Items)
    {
        var pet = await _context.Pets.FindAsync(itemDto.PetId);
        
        // Validate tồn tại
        if (pet == null) return BadRequest($"Pet ID {itemDto.PetId} không tồn tại.");
        
        // Validate số lượng yêu cầu
        if (itemDto.Quantity <= 0) return BadRequest("Số lượng phải > 0.");
        
        // Validate hàng tồn
        if (pet.Quantity < itemDto.Quantity) return BadRequest($"Không đủ hàng cho {pet.Name}.");

        var orderItem = new PurchaseItem
        {
            PetId = pet.Id,
            Quantity = itemDto.Quantity,
            UnitPrice = pet.Price // Lấy giá lúc đặt
        };

        totalAmount += orderItem.Quantity * orderItem.UnitPrice;
        order.PurchaseItems.Add(orderItem);

        // (Tùy chọn) Trừ số lượng tồn kho
        pet.Quantity -= itemDto.Quantity; 
    }

    order.TotalAmount = totalAmount;

    _context.PurchaseOrders.Add(order);
    await _context.SaveChangesAsync();

    // 4. Trả 201 Created (không phải 200 Ok)
    // Slide Testing (Chapter 6, demo PostOrder_Returns201Created) assert đúng HttpStatusCode.Created
    return CreatedAtAction(nameof(GetOrderById), new { id = order.Id }, order);
}

[HttpGet("{id}")]
[Authorize]
public async Task<IActionResult> GetOrderById(int id)
{
    var order = await _context.PurchaseOrders
        .Include(o => o.PurchaseItems)
        .FirstOrDefaultAsync(o => o.Id == id);
    if (order == null) return NotFound();
    return Ok(order);
}

⚠️ Đề Q3 ghi rõ: "userId in route must match userId in JWT token" — không có ngoại lệ cho Admin ở route này. Admin xem toàn bộ đơn qua route riêng GET /api/orders ở trên, KHÔNG bypass check ở route này. 
[HttpGet("user/{userId}")]
[Authorize]
public async Task<IActionResult> GetOrdersByUser(int userId)
{
    var tokenUserId = User.FindFirst(ClaimTypes.NameIdentifier)?.Value;

    // Chỉ chính User đó mới được xem (không có ngoại lệ Admin ở route này)
    if (tokenUserId != userId.ToString())
    {
        return Forbid(); // Trả về 403
    }

    var orders = await _context.PurchaseOrders
        .Include(o => o.PurchaseItems)
        .Where(o => o.UserId == userId)
        .ToListAsync();

    return Ok(orders);
}

8 JWT Authentication & Authorization

AuthController (Login)

Đề bài cho phép lưu password dưới dạng Plain Text để test. Chú ý Claim NameIdentifier dùng để lưu UserId.

[ApiController]
[Route("api/[controller]")]
public class AuthController : ControllerBase
{
    private readonly AppDbContext _context;
    private readonly IConfiguration _config;

    public AuthController(AppDbContext context, IConfiguration config)
    {
        _context = context; _config = config;
    }

    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginDto dto)
    {
        var user = await _context.Users.FirstOrDefaultAsync(u => u.Email == dto.Email && u.Password == dto.Password);
        if (user == null) return BadRequest("Sai email hoặc password.");

        var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_config["Jwt:Key"]));
        var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

        var claims = new[]
        {
            new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
            new Claim(ClaimTypes.Email, user.Email),
            new Claim(ClaimTypes.Role, user.Role) // Dùng để Authorize
        };

        var token = new JwtSecurityToken(
            issuer: _config["Jwt:Issuer"],
            audience: _config["Jwt:Audience"],
            claims: claims,
            expires: DateTime.Now.AddHours(1),
            signingCredentials: creds
        );

        return Ok(new { token = new JwtSecurityTokenHandler().WriteToken(token) });
    }
}

IRepository<T> — Interface generic (khác Repository Layer đề thi)

So sánh: đề thi (Q1/Q3) yêu cầu IFruitRepository/IPetRepository viết tay từng method cho 1 entity. Lab 8 dùng where T : class để 1 interface áp dụng được cho bất kỳ entity (Book, Author, Category...) mà không cần viết lại. 
public interface IRepository<T> where T : class
{
    Task<IEnumerable<T>> GetAllAsync();
    Task<T?> GetByIdAsync(int id);
    Task<T> AddAsync(T entity);
    Task<T?> UpdateAsync(int id, T entity);
    Task<bool> DeleteAsync(int id);
}

BookRepository — implement generic interface

public class BookRepository : IRepository<Book>
{
    private readonly AppDbContext _context;
    public BookRepository(AppDbContext context) => _context = context;

    public async Task<IEnumerable<Book>> GetAllAsync() =>
        await _context.Books.ToListAsync();

    public async Task<Book?> GetByIdAsync(int id) =>
        await _context.Books.FindAsync(id);

    public async Task<Book> AddAsync(Book entity)
    {
        _context.Books.Add(entity);
        await _context.SaveChangesAsync();
        return entity;
    }

    public async Task<Book?> UpdateAsync(int id, Book entity)
    {
        var existing = await _context.Books.FindAsync(id);
        if (existing == null) return null;

        // Cập nhật từng field (không Update() nguyên object để tránh ghi đè Id)
        existing.Title = entity.Title;
        existing.Author = entity.Author;
        existing.Year = entity.Year;
        existing.Genre = entity.Genre;

        await _context.SaveChangesAsync();
        return existing;
    }

    public async Task<bool> DeleteAsync(int id)
    {
        var existing = await _context.Books.FindAsync(id);
        if (existing == null) return false;

        _context.Books.Remove(existing);
        await _context.SaveChangesAsync();
        return true;
    }
}

[ApiController]
[Route("api/[controller]")]
public class BooksController : ControllerBase
{
    private readonly IRepository<Book> _repo;
    public BooksController(IRepository<Book> repo) => _repo = repo;

    [HttpGet]
    public async Task<IActionResult> GetAllBooks()
    {
        var books = await _repo.GetAllAsync();
        return Ok(books);
    }

    [HttpGet("{id}")]
    public async Task<IActionResult> GetBookById(int id)
    {
        var book = await _repo.GetByIdAsync(id);
        if (book == null) return NotFound();
        return Ok(book);
    }

    [HttpPost]
    public async Task<IActionResult> CreateBook([FromBody] Book book)
    {
        if (!ModelState.IsValid) return BadRequest(ModelState);
        var created = await _repo.AddAsync(book);
        return CreatedAtAction(nameof(GetBookById), new { id = created.Id }, created);
    }

    [HttpPut("{id}")]
    public async Task<IActionResult> UpdateBook(int id, [FromBody] Book book)
    {
        var updated = await _repo.UpdateAsync(id, book);
        if (updated == null) return NotFound();
        return Ok(updated);
    }

    [HttpDelete("{id}")]
    public async Task<IActionResult> DeleteBook(int id)
    {
        var deleted = await _repo.DeleteAsync(id);
        if (!deleted) return NotFound();
        return NoContent();
    }
}
