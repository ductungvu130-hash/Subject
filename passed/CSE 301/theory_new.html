SELECT & WHERE — Truy vấn cơ bản

Mọi câu query đều bắt đầu từ đây. Hãy hiểu rõ thứ tự thực thi của MySQL — nó không chạy theo thứ tự bạn viết.

⚙️ Thứ tự thực thi thực sự của MySQL

Cú pháp SELECT đầy đủ

sql — Template (chỉ dùng những gì cần)
SELECT   [DISTINCT] cột1, cột2, COUNT(*), SUM(cột)
FROM     tên_bảng [AS alias]
[JOIN    bảng2 ON điều_kiện]
[WHERE   điều_kiện_lọc_hàng]
[GROUP BY cột_nhóm]
[HAVING  điều_kiện_lọc_nhóm]
[ORDER BY cột ASC/DESC]
[LIMIT   n];

JOIN 3 bảng — Pattern chuẩn trong đề thi

sql — Tên khách + sản phẩm + số lượng từng đơn
SELECT
    c.full_name,
    p.product_name,
    od.quantity,
    od.quantity * od.unit_price AS thanh_tien
FROM   order_header oh
JOIN   customer     c  ON c.customer_id  = oh.customer_id   -- lấy tên khách
JOIN   order_detail od ON od.order_id    = oh.order_id      -- lấy chi tiết
JOIN   product      p  ON p.product_id   = od.product_id    -- lấy tên SP
WHERE  oh.status = 'completed';
✅ Mẹo đọc JOIN cho dễ nhớ
Bắt đầu từ bảng trung tâm (order_header), rồi JOIN ra các bảng xung quanh theo quan hệ khóa ngoại. Luôn đặt alias ngắn (oh, c, od, p) để tránh nhầm lẫn.

🚨 Bẫy Tích Descartes — Lỗi phổ biến nhất

❌ JOIN đồng thời 2 bảng "nhiều" → kết quả SAI

Đơn #3 có 4 sản phẩm trong order_detail + 1 thanh toán trong payment:
JOIN cả 2 vào → 4 × 1 = 4 hàng → SUM(payment.amount) bị nhân 4 lần = SAI!

✅ Giải pháp: Scalar Subquery riêng biệt
(SELECT SUM(od.quantity * od.unit_price) FROM order_detail od WHERE od.order_id = oh.order_id)
(SELECT COALESCE(SUM(p.amount),0) FROM payment p WHERE p.order_id = oh.order_id)
Mỗi subquery tính độc lập → không gây tích Descartes → kết quả đúng.

sql — Query hoàn chỉnh với GROUP BY + HAVING
SELECT
    c.full_name,
    COUNT(oh.order_id)    AS total_orders,   -- đếm số đơn mỗi khách
    SUM(oh.total_amount)  AS total_spent      -- cộng tổng tiền
FROM   customer     c
JOIN   order_header oh ON c.customer_id = oh.customer_id
GROUP BY c.customer_id, c.full_name           -- gom nhóm theo từng khách
HAVING   COUNT(oh.order_id) >= 2             -- chỉ lấy khách có ít nhất 2 đơn
ORDER BY total_spent DESC;

❌ SAI: WHERE với aggregate
GROUP BY customer_id
WHERE COUNT(*) >= 2  -- LỖI SYNTAX!
WHERE chạy TRƯỚC GROUP BY → chưa có COUNT().
✅ ĐÚNG: HAVING sau GROUP BY
GROUP BY customer_id
HAVING COUNT(*) >= 2  -- Đúng!
HAVING chạy SAU GROUP BY → đã có COUNT().
💡 Quy tắc GROUP BY bắt buộc
Mọi cột trong SELECT mà không nằm trong hàm aggregate đều phải có trong GROUP BY.
Ví dụ: SELECT customer_id, full_name, COUNT(*)
→ GROUP BY customer_id, full_name ✅ (COUNT(*) là aggregate, không cần thêm)

Subquery — Truy vấn lồng nhau

Subquery là SELECT nằm bên trong SELECT khác. MySQL chạy subquery trước, lấy kết quả, rồi dùng vào query ngoài.

Loại 1: Subquery trong WHERE với IN

Dùng khi muốn lọc theo điều kiện cần JOIN nhiều bảng.

sql — Tìm khách đã mua Laptop ít nhất 1 lần
SELECT customer_id, full_name
FROM   customer
WHERE  customer_id IN (
    -- Bước 1: Subquery tìm tập customer_id đã mua Laptop
    SELECT DISTINCT oh.customer_id
    FROM   order_header oh
    JOIN   order_detail od ON oh.order_id   = od.order_id
    JOIN   product      p  ON od.product_id = p.product_id
    WHERE  p.category = 'Laptop'
    -- Subquery trả về: [1, 2, 3, 4, 5, 7, 8, 9, 11, 12]
);
-- Bước 2: Lọc customer WHERE customer_id IN [1,2,3,4,5,7,8,9,11,12]

Loại 2: Scalar Subquery trong SELECT

Trả về đúng 1 giá trị cho mỗi hàng của query ngoài. Giải pháp cho bài toán tính tổng từ 2 bảng quan hệ N.

sql — Đơn hàng + tổng đã thanh toán + còn nợ
SELECT
    oh.order_id,
    oh.total_amount,
    -- Scalar subquery: chạy 1 lần cho TỪNG hàng order_header
    (SELECT COALESCE(SUM(amount), 0)
     FROM   payment
     WHERE  order_id = oh.order_id)   AS da_thanh_toan,
    oh.total_amount
    - (SELECT COALESCE(SUM(amount), 0)
       FROM   payment
       WHERE  order_id = oh.order_id) AS con_no
FROM  order_header oh;

Loại 3: OR với 2 Subquery — Dạng "High-Value Customer"

Đây là dạng thường xuất hiện ở câu 3 Section 1. Điều kiện OR nhưng mỗi vế cần logic phức tạp riêng.

sql — Mua Laptop ≥1 lần OR tổng chi tiêu > 100 triệu
SELECT DISTINCT   -- DISTINCT vì một khách có thể thỏa cả 2 điều kiện
    c.customer_id,
    c.full_name,
    c.email
FROM customer c
WHERE
    -- ĐK 1: Đã mua Laptop ít nhất 1 lần
    c.customer_id IN (
        SELECT oh.customer_id
        FROM   order_header oh
        JOIN   order_detail od ON oh.order_id   = od.order_id
        JOIN   product      p  ON od.product_id = p.product_id
        WHERE  p.category = 'Laptop'
    )
    OR
    -- ĐK 2: Tổng chi tiêu vượt 100 triệu
    c.customer_id IN (
        SELECT   customer_id
        FROM     order_header
        GROUP BY customer_id
        HAVING   SUM(total_amount) > 100000000
    );
✅ Tại sao DISTINCT?
Một khách thỏa cả ĐK1 (mua Laptop) lẫn ĐK2 (chi > 100M) → sẽ khớp ở cả 2 subquery → xuất hiện 2 lần → DISTINCT loại bỏ trùng lặp.

View là một câu SELECT được đặt tên và lưu trong database. Query view giống query bảng thật — MySQL tự chạy SELECT định nghĩa của view mỗi lần.

Cú pháp CREATE VIEW

sql
CREATE VIEW tên_view AS

CREATE OR REPLACE VIEW tên_view AS
SELECT ...;           -- tạo mới hoặc ghi đè nếu đã tồn tại

SELECT * FROM tên_view;   -- dùng như bảng thật

Ví dụ: v_order_invoice với Scalar Subquery

❌ JOIN trực tiếp → Tích Descartes → Kết quả SAI
Đơn #3: 4 sản phẩm × 1 payment = 4 dòng → SUM(payment.amount) × 4 = SAI!
sql — v_order_invoice ĐÚNG (scalar subquery)
CREATE VIEW v_order_invoice AS
SELECT
    oh.order_id,
    c.full_name                                    AS customer_name,
    oh.order_date,
    -- ① Tổng tiền hàng: subquery riêng tránh Descartes
    (SELECT SUM(od.quantity * od.unit_price)
     FROM   order_detail od
     WHERE  od.order_id = oh.order_id)             AS total_product_amount,
    -- ② Tổng đã thanh toán: COALESCE xử lý đơn chưa có payment
    (SELECT COALESCE(SUM(p.amount), 0)
     FROM   payment p
     WHERE  p.order_id = oh.order_id)              AS total_payment,
    -- ③ Còn nợ = tiền hàng - đã trả
    (SELECT SUM(od.quantity * od.unit_price)
     FROM   order_detail od
     WHERE  od.order_id = oh.order_id)
    -(SELECT COALESCE(SUM(p.amount), 0)
      FROM   payment p
      WHERE  p.order_id = oh.order_id)             AS balance
FROM   order_header oh
JOIN   customer     c ON c.customer_id = oh.customer_id;

Stored Procedure — Thủ tục lưu trữ

Stored Procedure là khối lệnh SQL có tên, lưu trong DB. Nhận tham số đầu vào, thực hiện logic (IF, vòng lặp), gọi bằng CALL.

💡 Tại sao phải đổi DELIMITER?
MySQL dùng ; để kết thúc lệnh. Bên trong Procedure cũng có nhiều ; → MySQL bị nhầm và báo lỗi trước khi tạo xong procedure.
Giải pháp: đổi delimiter sang $$ tạm thời → viết toàn bộ procedure → đổi lại ;.
($$ chỉ là quy ước, có thể dùng // hay bất kỳ chuỗi nào.)

Cú pháp — Giải thích từng thành phần

sql — sp_create_order từ đề thi TechNova Q2
DELIMITER $$   -- ① Đổi delimiter, MySQL không kết thúc ở ";" nữa

CREATE PROCEDURE sp_create_order(
    -- ② IN = tham số đầu vào (tiền tố p_ = parameter)
    IN p_customer_id  INT,
    IN p_product_id   INT,
    IN p_quantity     INT
)
BEGIN     -- ③ Bắt đầu khối lệnh

    -- ④ DECLARE: khai báo biến cục bộ (tiền tố v_ = variable)
    --    Phải đặt NGAY ĐẦU BEGIN, trước bất kỳ lệnh nào!
    DECLARE v_stock    INT;
    DECLARE v_price    DECIMAL(15,2);
    DECLARE v_order_id INT;

    -- ⑤ SELECT INTO: gán kết quả query vào biến (phải trả đúng 1 hàng)
    SELECT stock_quantity, unit_price
    INTO   v_stock, v_price
    FROM   product
    WHERE  product_id = p_product_id;

    -- ⑥ IF...THEN...END IF: kiểm tra điều kiện
    IF v_stock < p_quantity THEN
        -- ⑦ SIGNAL: ném lỗi, dừng procedure, hủy mọi thay đổi
        SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'Insufficient stock';
    END IF;

    -- ⑧ INSERT vào bảng cha
    INSERT INTO order_header (customer_id, order_date, status, total_amount)
    VALUES (p_customer_id, CURDATE(), 'pending', 0);

    -- ⑨ LAST_INSERT_ID(): lấy AUTO_INCREMENT ID vừa được tạo
    SET v_order_id = LAST_INSERT_ID();

    -- ⑩ INSERT vào bảng con (dùng v_order_id vừa lấy)
    INSERT INTO order_detail (order_id, product_id, quantity, unit_price)
    VALUES (v_order_id, p_product_id, p_quantity, v_price);

    -- ⑪ UPDATE tồn kho
    UPDATE product
    SET    stock_quantity = stock_quantity - p_quantity
    WHERE  product_id = p_product_id;

END $$    -- ⑫ Kết thúc procedure bằng $$

DELIMITER ;   -- ⑬ Trả delimiter về ";" như bình thường

Cách gọi procedure

sql
CALL sp_create_order(1, 2, 1);         -- khách #1 mua SP #2, số lượng 1
CALL sp_create_order(1, 2, 99999);     -- lỗi "Insufficient stock" nếu stock < 99999

Ví dụ 1: AFTER INSERT — Cập nhật total_amount tự động

sql — trg_update_order_total
DELIMITER $$
CREATE TRIGGER trg_update_order_total
AFTER INSERT ON order_detail  -- sự kiện: sau khi INSERT order_detail
FOR EACH ROW                   -- chạy cho từng dòng được INSERT
BEGIN
    DECLARE v_status VARCHAR(20);

    -- NEW.order_id = order_id của dòng order_detail vừa thêm
    SELECT status INTO v_status
    FROM   order_header
    WHERE  order_id = NEW.order_id;

    IF v_status != 'cancelled' THEN
        UPDATE order_header
        SET    total_amount = (
            -- Tính lại TOÀN BỘ đơn (không chỉ dòng mới)
            SELECT SUM(quantity * unit_price)
            FROM   order_detail
            WHERE  order_id = NEW.order_id
        )
        WHERE  order_id = NEW.order_id;
    END IF;
END $$
DELIMITER ;
Minh họa: INSERT thêm Anker Charger (890,000) vào đơn #5:
→ AFTER INSERT chạy → Tính lại SUM(order_detail WHERE order_id=5) = 28,550,000
→ UPDATE order_header SET total_amount = 28,550,000 WHERE order_id = 5

Ví dụ 2: BEFORE INSERT — Chặn dữ liệu không hợp lệ

sql — trg_check_payment_limit
DELIMITER $$
CREATE TRIGGER trg_check_payment_limit
BEFORE INSERT ON payment  -- BEFORE để có thể chặn bằng SIGNAL
FOR EACH ROW
BEGIN
    DECLARE v_order_total  DECIMAL(15,2);
    DECLARE v_already_paid DECIMAL(15,2);

    SELECT total_amount INTO v_order_total
    FROM   order_header
    WHERE  order_id = NEW.order_id;

    SELECT COALESCE(SUM(amount), 0) INTO v_already_paid
    FROM   payment
    WHERE  order_id = NEW.order_id;

    -- Nếu tổng sau khi thêm > total_amount → chặn
    IF v_already_paid + NEW.amount > v_order_total THEN
        SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = 'Payment exceeds order total amount';
    END IF;
END $$
DELIMITER ;

Index & Tối ưu — Tăng tốc với 15 triệu bản ghi

Index là cấu trúc dữ liệu bổ sung (B-tree) giúp MySQL tìm kiếm nhanh hơn, tương tự mục lục của cuốn sách.

❌ Không có Index
Query: WHERE order_date = '2025-06-01'
MySQL quét toàn bộ 15 triệu hàng → kiểm tra từng hàng → Full Table Scan
⏱ Vài giây đến vài phút
✅ Có Index trên order_date
Query: WHERE order_date = '2025-06-01'
MySQL tra B-tree → nhảy thẳng đến vị trí → đọc vài hàng → Index Scan
⏱ Dưới 10ms

Cú pháp tạo Index

sql
-- Index đơn trên 1 cột
CREATE INDEX idx_order_date ON order_header(order_date);

-- Unique Index: đồng thời ràng buộc không trùng
CREATE UNIQUE INDEX idx_email ON customer(email);

-- Composite Index: tối ưu query lọc cả status lẫn ngày
CREATE INDEX idx_status_date ON order_header(status, order_date);

🔥 Hàm phá Index — Câu hỏi chắc chắn trong đề!

Index B-tree lưu giá trị gốc đã sắp xếp:

2024-01-10 → row1  |  2024-01-15 → row2  |  2024-02-02 → row3  |  ... 15 triệu bản ghi ...
✅ BETWEEN — Dùng được Index
WHERE order_date
  BETWEEN '2025-01-01'
  AND '2025-12-31'

MySQL nhảy thẳng đến 2025-01-01 trong B-tree index, đọc đến 2025-12-31, dừng. Không cụm tất cả 15M hàng.

❌ YEAR() — Phá Index
WHERE YEAR(order_date)
  = 2025

MySQL phải tính YEAR() cho từng hàng. Index lưu 2024-01-10 chứ không lưu 2024 → không tra được. → Full Scan 15M hàng.

Nguyên tắc: Cột index bị bọc trong bất kỳ hàm nào ở WHERE → index vô dụng → Full Table Scan.
Áp dụng cho: YEAR(), MONTH(), DATE(), LOWER(), col+1=5, v.v.

Constraint — Ràng buộc toàn vẹn dữ liệu

sql — 5 loại constraint cần biết
CREATE TABLE ví_dụ (
    id        INT AUTO_INCREMENT PRIMARY KEY,  -- PK: không null, không trùng
    full_name VARCHAR(100) NOT NULL,               -- bắt buộc có giá trị
    email     VARCHAR(100) UNIQUE,               -- không cho trùng
    status    VARCHAR(20)  DEFAULT 'pending',   -- giá trị mặc định
    price     DECIMAL(15,2) NOT NULL,
    CONSTRAINT chk_price CHECK (price > 0),      -- điều kiện tùy chỉnh (MySQL 8+)
    customer_id INT NOT NULL,
    CONSTRAINT fk_cust
        FOREIGN KEY (customer_id)
        REFERENCES customer(customer_id)          -- ràng buộc tham chiếu
        ON DELETE RESTRICT                        -- không cho xóa nếu còn tham chiếu
        ON UPDATE CASCADE                         -- tự cập nhật khi ID thay đổi
);
