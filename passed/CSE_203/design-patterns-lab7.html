Kiến thức nền tảng

Design Pattern là gì?

Design Pattern (mẫu thiết kế) là những giải pháp tái sử dụng được đúc kết từ kinh nghiệm thực tiễn để giải quyết các bài toán lập trình hướng đối tượng thường gặp. Chúng không phải code có thể copy-paste — chúng là bản thiết kế tư duy.

🏗️

Creational Patterns (Mẫu Khởi tạo)

Kiểm soát cách tạo đối tượng. Tách logic khởi tạo khỏi logic sử dụng. Ví dụ: Singleton, Factory, Builder, Prototype.

🔧

Structural Patterns (Mẫu Cấu trúc)

Xác định cách kết hợp các class/object thành cấu trúc lớn hơn. Ví dụ: Decorator, Adapter, Proxy, Facade.

🔄

Behavioral Patterns (Mẫu Hành vi)

Xác định cách giao tiếp và phân phối trách nhiệm giữa các object. Ví dụ: Strategy, Observer, Command, Iterator.

🔒

Singleton

Đảm bảo một class chỉ có duy nhất một instance trong toàn bộ chương trình và cung cấp điểm truy cập toàn cục.

Creational
🏭

Factory Method

Định nghĩa interface để tạo object, nhưng để subclass quyết định class nào sẽ được khởi tạo. Tách client khỏi chi tiết khởi tạo.

Creational
🎀

Decorator

Bổ sung hành vi cho object trong lúc runtime mà không sửa đổi class gốc — bằng cách "bọc" object vào decorator.

Structural
🎯

Strategy

Định nghĩa một nhóm thuật toán có thể hoán đổi cho nhau. Client chọn thuật toán tại runtime mà không ảnh hưởng code khác.

Behavioral
📡

Observer

Thiết lập quan hệ 1-nhiều: khi một object thay đổi trạng thái, tất cả các object phụ thuộc sẽ được thông báo tự động.

Behavioral
💡 Nguyên tắc vàng: Các pattern đều tuân theo nguyên lý OCP (Open/Closed Principle) — code mở cho mở rộng, đóng cho sửa đổi — và DIP — phụ thuộc vào abstraction, không phụ thuộc vào implementation cụ thể.

Bài 1 · Creational Pattern

01

Singleton Pattern — Logger

🧠 Phân tích bài toán

  • Vấn đề: Ứng dụng cần một Logger duy nhất — nếu có nhiều instance thì log sẽ bị rời rạc, không nhất quán.
  • Giải pháp Singleton: Ẩn constructor (private), giữ instance trong static field, chỉ cấp phát qua getInstance().
  • Thread-safe: Dùng synchronized hoặc double-checked locking khi môi trường đa luồng.
📐 Class Diagram — Singleton
Logger.java 
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

public class Logger {

    // ① Static field giữ instance duy nhất
    private static Logger instance;

    // ② Constructor private — không ai tạo trực tiếp được
    private Logger() {
        System.out.println("Logger đã được khởi tạo.");
    }

    // ③ Điểm truy cập duy nhất — synchronized để thread-safe
    public static synchronized Logger getInstance() {
        if (instance == null) {
            instance = new Logger();
        }
        return instance;
    }

    // ④ Phương thức log với timestamp
    public void log(String message) {
        String timestamp = LocalDateTime.now()
            .format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"));
        System.out.println("[" + timestamp + "] " + message);
    }
}
Main.java 
public class Main {
    public static void main(String[] args) {

        // Lấy instance — Logger() chỉ được gọi lần đầu
        Logger logger1 = Logger.getInstance();
        logger1.log("Ứng dụng khởi động.");

        Logger logger2 = Logger.getInstance();
        logger2.log("Người dùng đã đăng nhập.");

        // Kiểm tra chỉ có 1 instance
        System.out.println("Cùng một instance? " + (logger1 == logger2));
    }
}
▶ Output mẫu
Logger đã được khởi tạo.
[2024-10-15 09:23:01] Ứng dụng khởi động.
[2024-10-15 09:23:01] Người dùng đã đăng nhập.
Cùng một instance? true

Bài 2 · Creational Pattern

02

Factory Method Pattern — Shape

🧠 Phân tích bài toán

  • Vấn đề: Client cần tạo các hình dạng khác nhau nhưng không muốn biết chi tiết khởi tạo.
  • Giải pháp: Mỗi loại hình có Factory riêng, implement method getShape() trừu tượng.
  • Lợi ích: Thêm hình mới (Triangle…) chỉ cần thêm class, không sửa code cũ — tuân thủ OCP.
📐 Class Diagram — Factory Method
Shape.java + Implementations + Factories + Main 
// ① Interface Shape
public interface Shape {
    void draw();
}

// ② Các class thực thi Shape
public class Circle implements Shape {
    @Override
    public void draw() { System.out.println("Drawing a Circle"); }
}

public class Rectangle implements Shape {
    @Override
    public void draw() { System.out.println("Drawing a Rectangle"); }
}

public class Square implements Shape {
    @Override
    public void draw() { System.out.println("Drawing a Square"); }
}

// ③ Abstract Factory
public abstract class ShapeFactory {
    public abstract Shape getShape();
}

// ④ Concrete Factories
public class CircleFactory extends ShapeFactory {
    @Override
    public Shape getShape() { return new Circle(); }
}

public class RectangleFactory extends ShapeFactory {
    @Override
    public Shape getShape() { return new Rectangle(); }
}

public class SquareFactory extends ShapeFactory {
    @Override
    public Shape getShape() { return new Square(); }
}

// ⑤ Main
public class Main {
    public static void main(String[] args) {
        ShapeFactory factory = new CircleFactory();
        factory.getShape().draw();          // Drawing a Circle

        factory = new RectangleFactory();
        factory.getShape().draw();          // Drawing a Rectangle

        factory = new SquareFactory();
        factory.getShape().draw();          // Drawing a Square
    }
}
▶ Output mẫu
Drawing a Circle
Drawing a Rectangle
Drawing a Square

Bài 3 · Structural Pattern

03

Decorator Pattern — Coffee

🧠 Phân tích bài toán

  • Vấn đề: Cà phê có nhiều lựa chọn thêm (milk, sugar, whipped cream). Nếu dùng kế thừa sẽ tạo ra bùng nổ class.
  • Giải pháp Decorator: Bọc object Coffee trong các Decorator, mỗi lớp bọc thêm cost và description.
  • Hình ảnh trực quan: Như bóc hành — mỗi lớp decorator là 1 lớp hành bao quanh object gốc.
  • Điểm chính: BaseDecorator implement cùng interface Coffee → có thể bọc lồng nhau vô hạn.
📐 Class Diagram — Decorator
Coffee + Decorators + Main.java 
// ① Interface gốc
public interface Coffee {
    double getCost();
    String getDescription();
}

// ② Component cơ bản
public class SimpleCoffee implements Coffee {
    @Override
    public double getCost() { return 2.0; }
    @Override
    public String getDescription() { return "Simple Coffee"; }
}

// ③ BaseDecorator — wraps một Coffee
public abstract class BaseDecorator implements Coffee {
    protected Coffee coffee;

    public BaseDecorator(Coffee coffee) {
        this.coffee = coffee;
    }

    @Override
    public double getCost() { return coffee.getCost(); }

    @Override
    public String getDescription() { return coffee.getDescription(); }
}

// ④ Concrete Decorators
public class MilkDecorator extends BaseDecorator {
    public MilkDecorator(Coffee c) { super(c); }

    @Override
    public double getCost() { return super.getCost() + 1.5; }

    @Override
    public String getDescription() { return super.getDescription() + " + Milk"; }
}

public class SugarDecorator extends BaseDecorator {
    public SugarDecorator(Coffee c) { super(c); }

    @Override
    public double getCost() { return super.getCost() + 0.5; }

    @Override
    public String getDescription() { return super.getDescription() + " + Sugar"; }
}

public class WhippedCreamDecorator extends BaseDecorator {
    public WhippedCreamDecorator(Coffee c) { super(c); }

    @Override
    public double getCost() { return super.getCost() + 2.0; }

    @Override
    public String getDescription() { return super.getDescription() + " + Whipped Cream"; }
}

// ⑤ Main — bọc lồng nhau như matryoshka
public class Main {
    public static void main(String[] args) {
        Coffee coffee = new SimpleCoffee();
        coffee = new MilkDecorator(coffee);
        coffee = new SugarDecorator(coffee);

        System.out.println("Description: " + coffee.getDescription());
        System.out.printf("Cost: $%.2f%n", coffee.getCost());
    }
}
▶ Output mẫu
Description: Simple Coffee + Milk + Sugar
Cost: $4.00

Bài 4 · Behavioral Pattern

04

Strategy Pattern — Shopping Cart

🧠 Phân tích bài toán

  • Vấn đề: ShoppingCart cần hỗ trợ nhiều phương thức thanh toán, và có thể thêm phương thức mới bất kỳ lúc nào.
  • Giải pháp Strategy: Tách thuật toán thanh toán ra ngoài Cart — Cart giữ tham chiếu đến PaymentStrategy.
  • Thay đổi runtime: Người dùng có thể đổi phương thức thanh toán trong lúc chạy chương trình.
  • So sánh vs if-else: Không có if-else dài dòng trong Cart — mỗi strategy tự xử lý logic riêng.
📐 Class Diagram — Strategy
Strategy + ShoppingCart + Main.java 
// ① ShoppingItem (data class)
public class ShoppingItem {
    private String description;
    private double cost;

    public ShoppingItem(String description, double cost) {
        this.description = description;
        this.cost = cost;
    }

    public double getCost() { return cost; }
    public String getDescription() { return description; }
}

// ② Strategy interface
public interface PaymentStrategy {
    void pay(double amount);
}

// ③ Concrete Strategies
public class CreditCardPayment implements PaymentStrategy {
    private String cardNumber;
    public CreditCardPayment(String cardNumber) { this.cardNumber = cardNumber; }

    @Override
    public void pay(double amount) {
        System.out.printf("Paid $%.2f using Credit Card (****%s)%n",
            amount, cardNumber.substring(cardNumber.length() - 4));
    }
}

public class PaypalPayment implements PaymentStrategy {
    private String email;
    public PaypalPayment(String email) { this.email = email; }

    @Override
    public void pay(double amount) {
        System.out.printf("Paid $%.2f via PayPal (%s)%n", amount, email);
    }
}

public class CashPayment implements PaymentStrategy {
    @Override
    public void pay(double amount) {
        System.out.printf("Paid $%.2f in Cash%n", amount);
    }
}

// ④ Context — ShoppingCart
import java.util.*;
public class ShoppingCart {
    private List<ShoppingItem> items = new ArrayList<>();
    private PaymentStrategy strategy;

    public void setStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    public void addItem(ShoppingItem item) { items.add(item); }

    public void checkout() {
        double total = items.stream().mapToDouble(ShoppingItem::getCost).sum();
        System.out.printf("Total amount: $%.2f%n", total);
        strategy.pay(total);
    }
}

// ⑤ Main
public class Main {
    public static void main(String[] args) {
        ShoppingCart cart = new ShoppingCart();
        cart.addItem(new ShoppingItem("Laptop", 80.0));
        cart.addItem(new ShoppingItem("Mouse", 20.0));

        cart.setStrategy(new CreditCardPayment("1234567890123456"));
        cart.checkout();

        cart.setStrategy(new PaypalPayment("user@email.com"));
        cart.checkout();
    }
}
▶ Output mẫu
Total amount: $100.00
Paid $100.00 using Credit Card (****3456)
Total amount: $100.00
Paid $100.00 via PayPal (user@email.com)

Bài 5 · Behavioral Pattern

05

Observer Pattern — News Agency

🧠 Phân tích bài toán

  • Vấn đề: NewsAgency cần thông báo tới nhiều subscriber khi có tin tức mới, nhưng không muốn biết cụ thể là ai đang đăng ký.
  • Giải pháp Observer: Subject (NewsAgency) giữ danh sách Observer, gọi update() trên tất cả khi có sự kiện.
  • Loose coupling: Subject chỉ biết Observer thông qua interface — có thể thêm/xóa subscriber bất kỳ lúc nào.
  • Thực tế: Pattern này là nền tảng của event system, React state, RxJava, EventBus…
📐 Class Diagram — Observer
Observer + Subject + NewsAgency + Main.java 
// ① Observer interface
public interface Observer {
    void update(String message);
}

// ② Subject class — quản lý danh sách observers
import java.util.*;
public class Subject {
    private List<Observer> observers = new ArrayList<>();

    public void addObserver(Observer o) { observers.add(o); }

    public void removeObserver(Observer o) { observers.remove(o); }

    public void notifyObservers(String message) {
        for (Observer o : observers) {
            o.update(message);
        }
    }
}

// ③ Concrete Observers
public class EmailSubscriber implements Observer {
    private String email;
    public EmailSubscriber(String email) { this.email = email; }

    @Override
    public void update(String message) {
        System.out.println("Email Subscriber [" + email + "]: " + message);
    }
}

public class SMSSubscriber implements Observer {
    private String phone;
    public SMSSubscriber(String phone) { this.phone = phone; }

    @Override
    public void update(String message) {
        System.out.println("SMS Subscriber [" + phone + "]: " + message);
    }
}

// ④ NewsAgency — publisher
public class NewsAgency extends Subject {
    public void publishNews(String news) {
        System.out.println("\n[NewsAgency] Publishing: " + news);
        notifyObservers(news);
    }
}

// ⑤ Main
public class Main {
    public static void main(String[] args) {
        NewsAgency agency = new NewsAgency();

        Observer email = new EmailSubscriber("alice@mail.com");
        Observer sms   = new SMSSubscriber("0901234567");

        agency.addObserver(email);
        agency.addObserver(sms);
        agency.publishNews("Breaking News! AI takes over the world!");

        // Xóa 1 subscriber
        agency.removeObserver(sms);
        agency.publishNews("Second headline — SMS không còn nhận được.");
    }
}
▶ Output mẫu
[NewsAgency] Publishing: Breaking News! AI takes over the world!
Email Subscriber [alice@mail.com]: Breaking News! AI takes over the world!
SMS Subscriber [0901234567]: Breaking News! AI takes over the world!

[NewsAgency] Publishing: Second headline — SMS không còn nhận được.
Email Subscriber [alice@mail.com]: Second headline — SMS không còn nhận được.
