Factory Method · 70 điểm

Factory Method Pattern — Tổng quan

Định nghĩa (GoF): Define an interface for creating an object, but let subclasses decide which class to instantiate. Factory Method lets a class defer instantiation to subclasses.

Một câu nhớ mãi: Factory Method = "Tôi cần tạo object, nhưng để subclass quyết định tạo loại nào."
Creator khai báo factory method → ConcreteCreator override và trả về ConcreteProduct tương ứng.

Pattern type

Creational — kiểm soát cách tạo object

Also known as

Virtual Constructor

Keyword

abstract method trả về kiểu Product interface

Khi nào dùng

Không biết trước loại object cần tạo; muốn subclass kiểm soát

Factory Method

Sơ đồ dưới đây mô tả luồng hoạt động của Factory Method: từ lúc Client gọi factory đến khi object được tạo và sử dụng.

⚠️ Hay nhầm khi thi: Creator KHÔNG phải chỉ là factory — Creator thường có thêm business logic. Factory method là một method trong Creator, không phải toàn bộ class. Creator phụ thuộc vào Product interface, không phụ thuộc ConcreteProduct.

📐 Factory Method — General Structure (GoF)

Factory Method

Các biến thể

① Abstract Creator (chuẩn GoF)

Creator là abstract class, factoryMethod() là abstract. Subclass bắt buộc override. Đây là dạng Lab 7 yêu cầu.

② Default Implementation

Creator là class thường, factory method có default implementation. Subclass có thể override hoặc không.

③ Parameterized Factory

Factory method nhận tham số String/Enum để quyết định loại object. Dùng switch bên trong — vi phạm OCP.

④ Static Factory Method

Method là static — không cần tạo factory object. Không phải Factory Method thuần túy vì không dùng polymorphism.

Ví dụ 1 — Shape Factory (Lab 7)

Shape.java — Product interface
public interface Shape {
    void draw();
}
Circle.java · Rectangle.java · Square.java — ConcreteProduct
public class Circle implements Shape {
    @Override
    public void draw() { System.out.println("Drawing a Circle"); }
}

public class Rectangle implements Shape {
    @Override
    public void draw() { System.out.println("Drawing a Rectangle"); }
}

public class Square implements Shape {
    @Override
    public void draw() { System.out.println("Drawing a Square"); }
}
ShapeFactory.java — Abstract Creator
public abstract class ShapeFactory {

    public abstract Shape getShape();

    public void printShapeInfo() {
        Shape shape = getShape();
        System.out.print("Created: ");
        shape.draw();
    }
}
CircleFactory.java · RectangleFactory.java · SquareFactory.java — ConcreteCreator
public class CircleFactory extends ShapeFactory {
    @Override
    public Shape getShape() { return new Circle(); }
}

public class RectangleFactory extends ShapeFactory {
    @Override
    public Shape getShape() { return new Rectangle(); }
}

public class SquareFactory extends ShapeFactory {
    @Override
    public Shape getShape() { return new Square(); }
}
Main.java — Client
public class Main {
    public static void main(String[] args) {
        ShapeFactory factory = new CircleFactory();
        factory.getShape().draw();

        factory = new RectangleFactory();
        factory.getShape().draw();

        factory = new SquareFactory();
        factory.printShapeInfo();
    }
}
Output:
Drawing a Circle
Drawing a Rectangle
Created: Drawing a Square

Ví dụ 2 — Notification Factory

Bài toán: Hệ thống gửi thông báo qua nhiều kênh (Email, SMS, Push). Mỗi kênh có cách gửi khác nhau. Factory Method giúp thêm kênh mới mà không sửa code cũ.

Notification.java — Product
public interface Notification {
    void send(String message);
    String getChannel();
}
EmailNotification.java · SMSNotification.java · PushNotification.java — ConcreteProduct
public class EmailNotification implements Notification {
    private final String email;

    public EmailNotification(String email) { this.email = email; }

    @Override
    public void send(String message) {
        System.out.println("[EMAIL → " + email + "] " + message);
    }

    @Override
    public String getChannel() { return "Email"; }
}

public class SMSNotification implements Notification {
    private final String phone;

    public SMSNotification(String phone) { this.phone = phone; }

    @Override
    public void send(String message) {
        System.out.println("[SMS → " + phone + "] " + message);
    }

    @Override
    public String getChannel() { return "SMS"; }
}

public class PushNotification implements Notification {
    private final String deviceId;

    public PushNotification(String deviceId) { this.deviceId = deviceId; }

    @Override
    public void send(String message) {
        System.out.println("[PUSH → device:" + deviceId + "] " + message);
    }

    @Override
    public String getChannel() { return "Push"; }
}
NotificationFactory.java — Abstract Creator (with template method)
public abstract class NotificationFactory {

    public abstract Notification createNotification();

    public void notify(String message) {
        Notification notification = createNotification();
        System.out.println("Sending via " + notification.getChannel() + "...");
        notification.send(message);
    }
}
EmailFactory.java · SMSFactory.java · PushFactory.java — ConcreteCreator
public class EmailFactory extends NotificationFactory {
    private final String email;
    public EmailFactory(String email) { this.email = email; }

    @Override
    public Notification createNotification() {
        return new EmailNotification(email);
    }
}

public class SMSFactory extends NotificationFactory {
    private final String phone;
    public SMSFactory(String phone) { this.phone = phone; }

    @Override
    public Notification createNotification() {
        return new SMSNotification(phone);
    }
}

public class PushFactory extends NotificationFactory {
    private final String deviceId;
    public PushFactory(String deviceId) { this.deviceId = deviceId; }

    @Override
    public Notification createNotification() {
        return new PushNotification(deviceId);
    }
}
Main.java
public class Main {
    public static void main(String[] args) {
        NotificationFactory factory;

        factory = new EmailFactory("alice@example.com");
        factory.notify("Your order has been placed!");

        factory = new SMSFactory("+84901234567");
        factory.notify("OTP: 482910");

        factory = new PushFactory("device-abc-123");
        factory.notify("You have a new message");
    }
}
Output:
Sending via Email...
[EMAIL → alice@example.com] Your order has been placed!
Sending via SMS...
[SMS → +84901234567] OTP: 482910
Sending via Push...
[PUSH → device:device-abc-123] You have a new message

Nguyên lý OOD áp dụng

Nguyên lýCách Factory Method áp dụng
OCP
Open/Closed		Thêm loại Product mới chỉ cần thêm class ConcreteProduct + ConcreteCreator. Không sửa Creator hay Client cũ.
DIP
Dependency Inversion		Client phụ thuộc vào Creator (abstract) và Product (interface), KHÔNG phụ thuộc vào ConcreteProduct hay ConcreteCreator.
SRP
Single Responsibility		Mỗi ConcreteCreator chỉ chịu trách nhiệm tạo một loại Product. Creator chứa business logic riêng tách biệt.
LSP
Liskov Substitution		Mọi ConcreteCreator có thể thay thế Creator mà không làm vỡ chương trình. Mọi ConcreteProduct có thể thay thế Product.

Factory Method · Thi

⚡ Kiến thức quan trọng & Lưu ý khi thi

🔑 Nhớ 4 thành phần

  • Product — interface/abstract cho object tạo ra
  • ConcreteProduct — hiện thực Product
  • Creator — abstract class, khai báo factory method
  • ConcreteCreator — override factory method

⚠️ Những lỗi hay mắc

  • Quên abstract cho Creator class và factory method
  • ConcreteCreator dùng implements thay vì extends
  • Trả về ConcreteProduct thay vì kiểu Product
  • Quên @Override trên factory method
  • Nhầm Factory Method với Simple Factory (không có abstract)

✅ Cấu trúc code đúng

  • Creator: public abstract class
  • Factory method: public abstract Product getX()
  • ConcreteCreator: extends Creator
  • Override: trả về new ConcreteProduct()
  • Client chỉ dùng biến kiểu Creator và Product

📐 Vẽ UML đúng

  • 2 hierarchy song song: Creator bên trái, Product bên phải
  • Creator → Product: dashed + open arrow (dependency/creates)
  • ConcreteCreator → Creator: solid + hollow triangle (extends)
  • ConcreteProduct → Product: dashed + hollow triangle (implements)
  • Ghi stereotype: «abstract», «interface»

⚠️ Khi đề yêu cầu thêm loại mới

  • Thêm Triangle implements Shape
  • Thêm TriangleFactory extends ShapeFactory
  • Override getShape() → return new Triangle()
  • KHÔNG sửa ShapeFactory, Client, hay class cũ nào

✅ Nguyên lý nào áp dụng?

  • OCP: mở rộng không sửa code cũ
  • DIP: client phụ thuộc abstraction
  • Factory Method = "Virtual Constructor"
  • Creator có thể chứa template method dùng factory method
📝 Template code nhanh cho thi — Factory Method:

interface Product { void doSomething(); }
class ConcreteProductA implements Product { public void doSomething() { ... } }
abstract class Creator { public abstract Product factoryMethod(); }
class ConcreteCreatorA extends Creator { public Product factoryMethod() { return new ConcreteProductA(); } }

Builder Pattern · 30 điểm

Builder Pattern — Tổng quan

Định nghĩa (GoF): Separate the construction of a complex object from its representation so that the same construction process can create different representations.

Một câu nhớ mãi: Builder = "Tôi cần xây object phức tạp theo nhiều bước, và muốn có thể tạo ra các phiên bản khác nhau bằng cùng quy trình."
Director điều phối → Builder thực hiện từng bước → ConcreteBuilder tạo ra Product cụ thể.

Pattern type

Creational — xây object phức tạp từng bước

Vấn đề

Constructor quá nhiều tham số (Telescoping Constructor anti-pattern)

Keyword

Từng bước (step by step) · Method chaining · Director

Khi nào dùng

Object phức tạp, nhiều thuộc tính tuỳ chọn, nhiều "preset" khác nhau

Builder

Nguyên lý hoạt động — Flow Diagram

Sơ đồ dưới đây mô tả luồng hoạt động của Builder: Director điều phối thứ tự build, Builder thực hiện từng bước, cuối cùng trả về Product hoàn chỉnh.

ProductHouseObject phức tạp cần xây dựng. Chứa nhiều thuộc tính. Không nhất thiết phải có interface chung giữa các Product khác nhau.

💡 Director không bắt buộc: Client có thể gọi trực tiếp các bước của Builder theo thứ tự tuỳ ý. Director chỉ cần khi muốn tái sử dụng chuỗi bước (buildMinimalHouse, buildLuxuryHouse).

Ví dụ 1 — House Builder

House.java — Product
public class House {
    private String walls;
    private String roof;
    private int windows;
    private boolean hasGarage;

    public void setWalls(String walls)    { this.walls = walls; }
    public void setRoof(String roof)      { this.roof = roof; }
    public void setWindows(int windows)  { this.windows = windows; }
    public void setHasGarage(boolean g)  { this.hasGarage = g; }

    @Override
    public String toString() {
        return "House{walls='" + walls + "', roof='" + roof
            + "', windows=" + windows + ", garage=" + hasGarage + "}";
    }
}
HouseBuilder.java — Builder interface (with method chaining)
public interface HouseBuilder {
    HouseBuilder buildWalls(String material);
    HouseBuilder buildRoof(String type);
    HouseBuilder addWindows(int count);
    HouseBuilder addGarage();
    House build();
}
WoodenHouseBuilder.java — ConcreteBuilder
public class WoodenHouseBuilder implements HouseBuilder {
    private final House house = new House();

    @Override
    public HouseBuilder buildWalls(String material) {
        house.setWalls("Wooden " + material);
        return this;
    }

    @Override
    public HouseBuilder buildRoof(String type) {
        house.setRoof("Wooden " + type + " roof");
        return this;
    }

    @Override
    public HouseBuilder addWindows(int count) {
        house.setWindows(count);
        return this;
    }

    @Override
    public HouseBuilder addGarage() {
        house.setHasGarage(true);
        return this;
    }

    @Override
    public House build() { return house; }
}
HouseDirector.java — Director
public class HouseDirector {
    public House buildMinimalHouse(HouseBuilder builder) {
        return builder.buildWalls("pine").buildRoof("flat").addWindows(2).build();
    }

    public House buildLuxuryHouse(HouseBuilder builder) {
        return builder.buildWalls("oak").buildRoof("gabled")
                       .addWindows(8).addGarage().build();
    }
}

public class Main {
    public static void main(String[] args) {
        HouseDirector director = new HouseDirector();

        House minimal = director.buildMinimalHouse(new WoodenHouseBuilder());
        System.out.println(minimal);

        House luxury = director.buildLuxuryHouse(new StoneHouseBuilder());
        System.out.println(luxury);

        House custom = new WoodenHouseBuilder()
            .buildWalls("cedar").addWindows(4).build();
        System.out.println(custom);
    }
}

House{walls='Stone oak', roof='Stone gabled roof', windows=8, garage=true}
House{walls='Wooden cedar', roof='null', windows=4, garage=false}

Ví dụ 2 — Pizza Builder

Bài toán: Hệ thống đặt pizza online. Mỗi pizza có đế, nước sốt, và nhiều topping tuỳ chọn. Builder giúp xây từng phần mà không cần constructor khổng lồ.

Pizza.java — Product
import java.util.*;

public class Pizza {
    private String dough;
    private String sauce;
    private List<String> toppings = new ArrayList<>();
    private String size;

    public void setDough(String dough)       { this.dough = dough; }
    public void setSauce(String sauce)       { this.sauce = sauce; }
    public void addTopping(String topping)   { toppings.add(topping); }
    public void setSize(String size)         { this.size = size; }

    @Override
    public String toString() {
        return size + " Pizza {" + "dough=" + dough
            + ", sauce=" + sauce + ", toppings=" + toppings + "}";
    }
}
PizzaBuilder.java — Builder interface
public interface PizzaBuilder {
    PizzaBuilder buildDough(String type);
    PizzaBuilder buildSauce(String sauce);
    PizzaBuilder addTopping(String topping);
    PizzaBuilder setSize(String size);

}

Builder · Thi

⚡ Kiến thức quan trọng & Lưu ý khi thi

🔑 Nhớ 4 thành phần

  • Product — object phức tạp được xây dựng
  • Builder — interface định nghĩa các bước
  • ConcreteBuilder — hiện thực steps + giữ state
  • Director — điều phối thứ tự (optional)

⚠️ Những lỗi hay mắc

  • Quên trả về this trong các build method
  • ConcreteBuilder không lưu state (house field)
  • Director nhận Product thay vì Builder
  • Quên method build() / getResult()
  • Nhầm Builder với Factory (Builder = nhiều bước!)

✅ Cấu trúc code đúng

  • Builder: public interface, mỗi method trả về Builder
  • ConcreteBuilder: implements Builder, có private Product p
  • Mỗi step: set thuộc tính product, return this
  • Director: nhận Builder interface, không biết ConcreteBuilder
  • build(): trả về Product hoàn chỉnh

📐 Vẽ UML đúng

  • Director ◇─── Builder (hollow diamond = aggregation)
  • ConcreteBuilder ──implements──▷ Builder (dashed + hollow triangle)
  • ConcreteBuilder ─────creates───▷ Product (dashed + open arrow)
  • Ghi «interface» cho Builder
  • Director KHÔNG trỏ trực tiếp vào Product hay ConcreteBuilder

⚠️ Director optional — câu trick

  • Đề hỏi "có cần Director không?" → KHÔNG bắt buộc
  • Client có thể gọi builder steps trực tiếp
  • Director chỉ hữu ích khi cần tái dùng chuỗi bước
  • Nếu đề yêu cầu Director → nhớ Director nhận Builder (interface), không nhận ConcreteBuilder

✅ Nguyên lý áp dụng

  • OCP: Thêm ConcreteBuilder mới không sửa Director
  • SRP: Director chỉ biết thứ tự, Builder biết cách build
  • DIP: Director phụ thuộc Builder interface
  • Builder giải quyết "Telescoping Constructor" anti-pattern
📝 Template code nhanh cho thi — Builder:

interface Builder { Builder stepA(); Builder stepB(); Product build(); }
class ConcreteBuilder implements Builder {
  private Product p = new Product();
  public Builder stepA() { p.setA(...); return this; }
  public Builder stepB() { p.setB(...); return this; }
  public Product build() { return p; }
}
class Director { public Product make(Builder b) { return b.stepA().stepB().build(); } }
