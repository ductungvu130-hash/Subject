Factory Method · 70 điểm

Factory Method Pattern

Định nghĩa: Factory Method là một Creational Design Pattern định nghĩa một interface/abstract method để tạo object, nhưng để các subclass quyết định class nào sẽ được instantiate. Factory Method cho phép class trì hoãn việc khởi tạo đến subclass.

🎯 Vấn đề giải quyết: Khi một class không thể biết trước nó cần tạo loại object nào, hoặc khi muốn để subclass chỉ định loại object được tạo — thay vì dùng new ConcreteClass() trực tiếp trong code.

Pattern type

Creational — kiểm soát cách tạo object

Intent

Define interface to create object; subclasses decide which class to instantiate

Also known as

Virtual Constructor

Key keyword

abstract method tạo object trả về kiểu interface/abstract

Khi nào dùng Factory Method?

1

Không biết trước loại object cần tạo

Client code cần làm việc với nhiều loại object khác nhau nhưng không biết trước loại nào.

2

Muốn subclass kiểm soát việc tạo object

Framework cần cung cấp hook để extension hoặc customization.

3

Tái sử dụng object hiện có

Khi muốn tái sử dụng object thay vì tạo mới mỗi lần (kết hợp với pool/cache).

Factory Method

Các thành phần (Participants)

Factory Method gồm 4 thành phần chính. Đây là phần hay bị hỏi trong thi — phải nhớ đúng tên và vai trò.

Thành phần Trong bài Lab (Shape) Vai trò
Product Shape (interface) Định nghĩa interface cho object được tạo ra. Đây là kiểu trả về của factory method.
ConcreteProduct Circle, Rectangle, Square Implement Product interface. Đây là object thực sự được tạo ra.
Creator ShapeFactory (abstract class) Khai báo factory method getShape() trả về kiểu Product. Creator có thể có default implementation.
ConcreteCreator CircleFactory, RectangleFactory, SquareFactory Override factory method để trả về ConcreteProduct tương ứng.
⚠️ Hay nhầm: Creator KHÔNG phải chỉ là factory — Creator thường có business logic khác. Factory method chỉ là một method trong Creator class, không phải toàn bộ class.

Factory Method

Các biến thể của Factory Method

Factory Method có nhiều cách hiện thực. Giáo trình OOD thường dạy cả 2 biến thể sau:

🔵 Biến thể 1 — Abstract Creator

Creator là abstract class, factory method là abstract. Subclass BẮT BUỘC phải override. Đây là dạng trong Lab 7.

🟠 Biến thể 2 — Default Implementation

Creator là class thường, factory method có default implementation. Subclass có thể override hoặc không.

🟢 Biến thể 3 — Parameterized Factory

Factory method nhận tham số để quyết định loại object. Dùng if-else hoặc switch bên trong.

🔴 Biến thể 4 — Static Factory Method

Factory method là static. Không cần tạo factory object. Không phải Factory Method thuần túy (vì không dùng polymorphism).

Biến thể 3: Parameterized Factory (hay gặp trong đề thi)

ShapeFactory.java — Parameterized 
public class ShapeFactory {

    public Shape createShape(String type) {
        if (type == null) return null;
        switch (type.toUpperCase()) {
            case "CIRCLE":    return new Circle();
            case "RECTANGLE": return new Rectangle();
            case "SQUARE":    return new Square();
            default:         return null;
        }
    }
}
⚠️ Vấn đề của Parameterized Factory: Vi phạm OCP — khi thêm shape mới phải sửa factory class. Biến thể 1 (Abstract Creator) giải quyết vấn đề này tốt hơn.

public class Main {

        ShapeFactory factory = new CircleFactory();

        factory = new RectangleFactory();
        factory.getShape().draw();

        factory = new SquareFactory();
        factory.getShape().draw();

Ví dụ nâng cao — Factory Method với tham số khởi tạo

Trong bài thi có thể yêu cầu ConcreteProduct có constructor với tham số. Ví dụ dưới đây cho thấy cách xử lý:

Logger Factory — Ví dụ nâng cao 
public interface Logger {
    void log(String message);
}

public class FileLogger implements Logger {
    private final String filename;
    public FileLogger(String filename) { this.filename = filename; }
    @Override
    public void log(String message) {
        System.out.println("[FILE:" + filename + "] " + message);
    }
}

public class ConsoleLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[CONSOLE] " + message);
    }
}

public abstract class LoggerFactory {
    public abstract Logger createLogger();

    public void logMessage(String msg) {
        Logger logger = createLogger();
        logger.log(msg);
    }
}

public class FileLoggerFactory extends LoggerFactory {
    private final String filename;
    public FileLoggerFactory(String filename) { this.filename = filename; }
    @Override
    public Logger createLogger() { return new FileLogger(filename); }
}

public class ConsoleLoggerFactory extends LoggerFactory {
    @Override
    public Logger createLogger() { return new ConsoleLogger(); }
}

Factory Method

Nguyên lý OOD liên quan

Nguyên lý Cách Factory Method áp dụng
OCP
Open/Closed Principle		 Thêm loại Shape mới chỉ cần thêm class mới (ConcreteProduct + ConcreteCreator), không sửa code cũ.
DIP
Dependency Inversion Principle		 Client code (Main) phụ thuộc vào abstraction (ShapeFactory, Shape), không phụ thuộc concrete class.
SRP
Single Responsibility Principle		 Mỗi Factory chỉ chịu trách nhiệm tạo một loại Shape. Creator class chứa business logic riêng.
LSP
Liskov Substitution Principle		 Mọi ConcreteCreator đều có thể thay thế ShapeFactory mà không làm vỡ chương trình.
🔑 Câu trả lời chuẩn khi bị hỏi "Factory Method áp dụng nguyên lý nào?":
Factory Method chủ yếu áp dụng OCP và DIP. OCP vì mở rộng không cần sửa code cũ. DIP vì Creator phụ thuộc vào Product interface, không phải ConcreteProduct.

Builder Pattern · 30 điểm

Builder Pattern

Định nghĩa: Builder là một Creational Design Pattern tách quá trình xây dựng (construction) của một object phức tạp ra khỏi biểu diễn (representation) của nó, cho phép cùng một quá trình xây dựng có thể tạo ra các biểu diễn khác nhau.

🎯 Vấn đề Builder giải quyết: Khi một object cần nhiều bước khởi tạo, hoặc constructor có quá nhiều tham số (Telescoping Constructor Anti-pattern). Builder tổ chức code theo từng bước rõ ràng.
  • Object phức tạp — nhiều thuộc tính, khởi tạo nhiều bước
  • Muốn xây dựng các "phiên bản" khác nhau của cùng loại object
  • Constructor với 8-10 tham số → khó đọc, dễ nhầm thứ tự
⚠️ Builder vs Factory Method:
Factory Method → tạo một object (focus: loại nào?)
Builder → tạo object phức tạp theo nhiều bước (focus: xây dựng như thế nào?)

Builder

Các thành phần của Builder

Thành phần Ví dụ (Xây nhà) Vai trò
Product House Object phức tạp cần xây dựng. Chứa nhiều thuộc tính, có thể có logic phức tạp.
Builder (interface) HouseBuilder Định nghĩa các bước xây dựng. Mỗi method xây một phần của Product.
ConcreteBuilder WoodenHouseBuilder, StoneHouseBuilder Hiện thực các bước xây dựng theo cách riêng. Cung cấp method getResult() trả về Product.
Director HouseDirector Điều phối thứ tự gọi các bước build. Client có thể dùng Director hoặc gọi Builder trực tiếp.
💡 Director là tùy chọn: Director không bắt buộc. Client code có thể gọi các bước của Builder theo thứ tự tự định. Director chỉ cần thiết khi muốn tái sử dụng cùng một chuỗi bước build cho nhiều loại Product.

Builder

Hiện thực Code Java — Đầy đủ

Bước 1 — Product class

House.java — Product 
public class House {
    private String walls;
    private String roof;
    private int windows;
    private boolean hasGarage;

    public void setWalls(String walls)      { this.walls = walls; }
    public void setRoof(String roof)        { this.roof = roof; }
    public void setWindows(int windows)    { this.windows = windows; }
    public void setHasGarage(boolean g)   { this.hasGarage = g; }

    @Override
    public String toString() {
        return "House {" +
            "walls='" + walls + "', roof='" + roof +
            "', windows=" + windows +
            ", garage=" + hasGarage + "}";
    }
}

Bước 2 — Builder interface

HouseBuilder.java — Builder interface 
public interface HouseBuilder {
    HouseBuilder buildWalls(String material);
    HouseBuilder buildRoof(String type);
    HouseBuilder addWindows(int count);
    HouseBuilder addGarage();
    House build();
}

Bước 3 — ConcreteBuilder

WoodenHouseBuilder.java 
public class WoodenHouseBuilder implements HouseBuilder {
    private final House house = new House();

    @Override
    public HouseBuilder buildWalls(String material) {
        house.setWalls("Wooden " + material);
        return this;
    }

    @Override
    public HouseBuilder buildRoof(String type) {
        house.setRoof("Wooden " + type + " roof");
        return this;
    }

    @Override
    public HouseBuilder addWindows(int count) {
        house.setWindows(count);
        return this;
    }

    @Override
    public HouseBuilder addGarage() {
        house.setHasGarage(true);
        return this;
    }

    @Override
    public House build() {
        return house;
    }
}

Bước 4 — Director (tùy chọn)

HouseDirector.java — Director 
public class HouseDirector {

    public House buildMinimalHouse(HouseBuilder builder) {
        return builder
            .buildWalls("pine")
            .buildRoof("flat")
            .addWindows(2)
            .build();
    }

    public House buildLuxuryHouse(HouseBuilder builder) {
        return builder
            .buildWalls("oak")
            .buildRoof("gabled")
            .addWindows(8)
            .addGarage()
            .build();
    }
}

Bước 5 — Client sử dụng

Main.java — Client code 
public class Main {
    public static void main(String[] args) {

        HouseDirector director = new HouseDirector();

        HouseBuilder woodenBuilder = new WoodenHouseBuilder();
        House minimalHouse = director.buildMinimalHouse(woodenBuilder);
        System.out.println(minimalHouse);

        HouseBuilder stoneBuilder = new StoneHouseBuilder();
        House luxuryHouse = director.buildLuxuryHouse(stoneBuilder);
        System.out.println(luxuryHouse);

        House customHouse = new WoodenHouseBuilder()
            .buildWalls("cedar")
            .addWindows(4)
            .build();
        System.out.println(customHouse);
    }
}
✅ Output:
House {walls='Wooden pine', roof='Wooden flat roof', windows=2, garage=false}
House {walls='Stone oak', roof='Stone gabled roof', windows=8, garage=true}
House {walls='Wooden cedar', roof='null', windows=4, garage=false}
💡 Method Chaining (Fluent Interface): Mỗi builder method trả về this (kiểu HouseBuilder) thay vì void. Đây là kỹ thuật giúp viết code theo dạng chuỗi: builder.buildWalls("oak").buildRoof("flat").addWindows(4).build(). Rất phổ biến trong thực tế (StringBuilder, Stream API).

So sánh

Builder vs Factory Method

Factory Method Builder
Mục tiêu Tạo object — quyết định loại nào Tạo object — quyết định xây như thế nào
Số bước Một bước — gọi factory method Nhiều bước — gọi từng build method
Product Thường đơn giản, một loại Phức tạp, nhiều thuộc tính, nhiều biến thể
Director Không có Có thể có (tùy chọn)
Polymorphism Dùng polymorphism (override factory method) Dùng interface + delegation
Ví dụ thực tế UI framework tạo button theo OS SQL query builder, HTTP request builder
