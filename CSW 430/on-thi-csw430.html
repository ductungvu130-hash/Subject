3. Cách tận dụng 6 trang tài liệu được phép khi thi

Đề đóng, không mang tài liệu riêng — nhưng 6 trang docs chính thức vẫn được mở. Biết chính xác cần tra trang nào, mục nào, và cách ghép code copy được vào bài làm sẽ tiết kiệm rất nhiều thời gian trong 90 phút.

3.1. Nguyên tắc chung khi lấy code từ docs

  1. Không copy-paste nguyên khối rồi chạy thẳng. Code mẫu trên docs luôn dùng data giả của riêng họ (ví dụ data={[{key: 'a'}]}) — phải đọc lướt để hiểu cấu trúc, rồi đổi tên biến/field cho khớp với data thật của đề (posts, users...).
  2. Dùng Ctrl+F (Cmd+F) ngay khi vào trang để nhảy thẳng đến tên component/API cần, không đọc từ đầu trang — các trang docs này rất dài.
  3. Ưu tiên phần "Example" / "Usage" — hầu hết trang đều có khối code mẫu chạy được ngay, thường ở đầu trang (React Navigation, Paper) hoặc cuối phần mô tả (React Native).
  4. Ghép theo khung "giữ cấu trúc — đổi nội dung": giữ nguyên phần khai báo component/props/import từ doc, chỉ đổi: (a) tên biến state, (b) nguồn dữ liệu (URL fetch thật thay vì data giả), (c) style/màu theo ý muốn.
  5. Nếu code mẫu báo lỗi thiếu prop lạ (do phiên bản thư viện trên Snack khác doc) — bỏ prop đó đi trước, ưu tiên chạy được cơ bản rồi mới thêm chi tiết.

3.3. Ví dụ ghép code thật — từ doc React Native FlatList

Doc reactnative.dev/docs/flatlist có sẵn ví dụ dạng này (data giả, key tự đặt):

// Code mau tren doc (rut gon)
<FlatList
  data={[{key: 'a'}, {key: 'b'}]}
  renderItem={({item}) => <Text>{item.key}</Text>}
/>

Ghép vào bài thi — giữ nguyên cấu trúc data/renderItem, chỉ đổi 3 chỗ: nguồn data (state fetch thật), field hiển thị (theo model của đề), và keyExtractor (doc dùng sẵn key trong object, còn API thật thường có id nên phải tự thêm keyExtractor):

<FlatList
  data={events}                                    {/* doi: data gia -> state that */}
  keyExtractor={(item) => item.id.toString()}       {/* them: doc khong can vi da co key san */}
  renderItem={({item}) => <Text>{item.title}</Text>} {/* doi: item.key -> item.title */}
/>

5.1. Nguyên tắc layout chung trong React Native

  • View giống <div> trong HTML — mặc định layout theo Flexbox, hướng mặc định là flexDirection: 'column' (xếp dọc).
  • Muốn xếp ngang (avatar + text cạnh nhau, nút bấm cạnh nhau) → thêm flexDirection: 'row'.
  • gap để tạo khoảng cách giữa các phần tử (thay vì margin từng cái) — hỗ trợ tốt trên Snack/Expo bản mới.
  • Toàn bộ chữ phải nằm trong <Text> — không được để text "trần" trong <View>, sẽ lỗi.
  • Dùng StyleSheet.create() ở cuối file thay vì style inline nhiều — vừa gọn code vừa dễ tái sử dụng giữa các screen.
// Khung flexbox dung lai duoc cho hau het cac card/row

6. Gọi API — GET / POST / PUT / DELETE

Cả 2 đề đều cho sẵn API REST chuẩn dạng https://dummyjson.com/<resource>. Học thuộc pattern này, đổi tên resource là dùng lại được hết.

GET danh sách (dùng cho màn Home/List)

useEffect(() => {
  const fetchData = async () => {
    try {
      setLoading(true);
      const res = await fetch('https://dummyjson.com/posts');
      const json = await res.json();
      setItems(json.posts); // chu y: dummyjson tra ve { posts: [...] } chu khong phai mang truc tiep
    } catch (error) {
      setErrorMsg("Couldn't load data. Please check your connection and try again.");

      setLoading(false);
    }
  };

}, []);

  try {

  const [description, setDescription] = useState('');
  const [tags, setTags] = useState('');
  const [errors, setErrors] = useState({});
  const [saving, setSaving] = useState(false);
  const [saveError, setSaveError] = useState('');

  const validate = () => {
    const e = {};
    if (title.trim().length < 3) e.title = 'Title must be at least 3 characters';
    if (description.trim().length < 10) e.description = 'Description must be at least 10 characters';
    setErrors(e);
    return Object.keys(e).length === 0;
  };

  const handleSubmit = async () => {
    if (!validate()) return; // dung lai, hien loi field
    try {
      setSaving(true);
      setSaveError('');
      const res = await fetch('https://dummyjson.com/posts/add', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ title, body: description, tags: tags.split(',').map(t=>t.trim()), userId: 5 }),
      });
      if (!res.ok) throw new Error();
      navigation.navigate('Home');
    } catch {
      setSaveError("Couldn't save. Please check your connection and try again.");
    } finally {
      setSaving(false);
    }
  };

  return (
    
      Title *
      
      {errors.title && {errors.title}}

      Description *
      
      {errors.description && {errors.description}}

      Tags (comma-separated)
      

      {saveError ? {saveError} : null}
      
        {saving ? 'Saving...' : 'Add Event'}
      
    
  );
}

9.5. Cách truyền dữ liệu giữa các màn: truyền id hay truyền cả object?

  • Truyền id (ví dụ navigate('Detail', {id: item.id})): màn đích phải tự fetch lại theo id trong useEffect. An toàn, đúng "chuẩn REST" nhất, dùng khi đề yêu cầu rõ "Use a GET request to fetch the details of the selected item".
  • Truyền cả object (ví dụ navigate('Edit', {post: item})): màn đích lấy luôn dữ liệu từ route.params.post, không cần fetch lại — tiết kiệm 1 lần gọi API, hợp lý cho màn Edit vì dữ liệu đã có sẵn ở Home. Cả 2 cách đều được chấp nhận, miễn code chạy đúng.
Sai phổ biến: quên đặt tên route trong Stack.Screen name="..." khớp với tên gọi trong navigation.navigate('...') — chỉ cần lệch 1 ký tự (hoa/thường) là app crash "screen not found".

import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import UsersScreen from './screens/UsersScreen';
import UserDetailScreen from './screens/UserDetailScreen';
import CartDetailScreen from './screens/CartDetailScreen';

const Stack = createNativeStackNavigator();

export default function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator initialRouteName="Users">
        <Stack.Screen name="Users" component={UsersScreen} />
        <Stack.Screen name="UserDetail" component={UserDetailScreen} options={{ title: 'User Detail' }} />
        <Stack.Screen name="CartDetail" component={CartDetailScreen} options={{ title: 'Cart Detail' }} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}
